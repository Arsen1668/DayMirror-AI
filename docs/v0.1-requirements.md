# DayMirror v0.1 产品需求与验收规范

版本：0.1.0。产品品牌：DayMirror；Skill 标识：daymirror。

## 1. 产品定位

构建基于长期生活记录、结构化数据和持续反馈的 AI 个人成长系统。第一版实现可持续积累的每日记录：AI 主动采访，用户逐题回答，形成同时适合阅读和脚本解析的日记。

目标用户是愿意回顾一天、但不想从空白页写日记的人。核心价值是还原具体经历、保留不确定性和积累可比较数据。v0.1 不根据一天的回答做人格结论，也不生成综合成长分。

## 2. 本版范围

包含两轮 10＋10 逐题问答、跳过、暂停、跨会话恢复、提前结束与部分日记、回答修正、结构化指标、自动总结保存、版本保留、中文文档、合成演示与测试。

不包含模型 API 接入、独立聊天窗口、云同步、加密、自动读取所有历史日记、周报/月报和自动追踪建议效果。Python 仅提供本地确定性工具；真实动态提问与总结由支持文件操作和脚本执行的 AI 客户端完成。

## 3. 访谈协议

第一轮 10 个问题依次覆盖：重要事件、时间分配、计划与完成任务、专注、分心、情绪与压力、睡眠饮食运动与精力、学习进展、交流和外部事件、满意与改进。

第二轮共 10 题，逐题参考已有全部回答生成下一题，围绕具体事件、潜在原因、可控条件、可尝试行为及验证方式展开。已提问题保存后保持稳定，恢复时不能重新生成同一题。

仅展示当前题目。允许用户不知道、不评分和跳过，不批量展示 20 题。问题文本在展示前持久化；回答原话在进入下一题前持久化。AI 解读与用户原话分开。

控制语义：

| 用户意图 | 系统行为 |
|---|---|
| 跳过 | 当前题标记 skipped，答案为 null，进入下一题 |
| 暂停 | 保存 paused 状态，保留当前题，不强制生成日记 |
| 继续 / 恢复 | 读取完整磁盘问答，继续当前未回答题 |
| 关闭客户端 | 已保存内容不丢失；再次恢复不依赖聊天记忆 |
| 提前结束并保存 | 总结已有回答，保存 interview_complete: false 的日记，之后仍可继续 |
| 修改第 N 题 | 更新已有题目原话，保留其他问答；已有日记时重新总结并保存新版本 |
| 完成 20 题 | 回答或跳过数达到 20，AI 自动总结并调用 save，无需再次确认 |

第一轮之后修正基础回答，保留已完成深入问题与答案，后续追问参考最新内容。普通补充澄清归入同一题，不增加标准题目总数。

## 4. 状态与恢复

会话状态为 active、paused、completed。active 且问题已全部处理时等待总结保存；成功保存完整日记后为 completed。部分日记保存后为 paused，恢复后为 active。

会话日期由指定时区计算，用户也可显式提供日期。恢复时不因跨午夜改变日期。工作空间初始化后保留时区；不同日期和同一天的多个会话分别保存。

JSON 是问答与进度的持久化来源；Markdown 是版本化的人类可读导出。会话包含 schema_version、唯一编号、日期、时区、时间戳、版本、当前题号、全部问答、最近总结输入及导出信息。接口详见 Skill 的 references/schema.md。

## 5. 数据标准

Markdown 使用 YAML frontmatter，schema_version 为 1。正文保留概览、事件、反思、收获、问题、明日行动及两轮原始问答。

指标为 sleep_hours、focus_minutes、planned_tasks、completed_tasks、mood、energy、stress、exercise_minutes。时长使用小时或分钟，任务数为非负整数，评分为 1–10 的整数。情绪和精力越高越积极/充沛，压力越高越大。

所有指标默认 null。用户明确报告的数据或无歧义的单位换算才可填写，每个非空指标保存来源问题编号。未报告评分不能从措辞猜测。任务完成数是计划内完成数，额外成果另写正文。

用户自述、主观感受和 AI 假设必须分开标注。总结与行动都引用已回答问题。AI 建议与用户行动意向分开；不能把建议记作已执行行为。数据不足时保留空内容。

脚本校验结构、范围、引用及进度一致性；自然语言证据是否支持数值仍由 AI 核对。自动测试不被描述为已经证明模型理解正确。

## 6. 架构与保存

可安装的 Skill 位于 daymirror/，包含入口指令、按需读取的访谈/数据/隐私说明、JSON 输入模板、合成夹具和 Python 工具。语言默认为中文；核心组织遵循 Agent Skills 规范，不绑定某个平台的模型 API。

Python 3.10+；依赖 PyYAML 和 tzdata，测试使用标准库 unittest。命令以 JSON 输入输出连接 AI 与工具，文本通过 UTF-8 输入文件或标准输入传递，不放入 shell 参数。

开发、测试及演示均位于指定 DayMirror 目录。默认用户数据目录为 private/workspace；安装到别处的用户可选择自己的工作空间。临时个人输入放在该工作空间 inputs/，不会进入 Skill 或示例目录。

写入顺序：校验输入 → 同目录临时文件写入和刷新 → 原子发布。会话文件可原子替换；日记按日期、会话编号、导出版本命名且保留旧版。重复保存相同内容返回原路径。写入失败不损坏已有文件；导出成功但更新会话失败时，同输入重试可恢复一致状态。

工作空间采用短时系统文件锁，阻止同时读写造成丢失；进程退出后锁自动释放。损坏 JSON、未知格式版本、过期总结、非法引用和冲突导出必须报错，不静默重置或覆盖。

记录问题、回答和跳过请求必须携带当前问题编号。重复相同请求幂等，不因客户端重试把答案或跳过状态记到下一题。

## 7. 隐私

默认本地明文保存。Python 不调用网络或模型服务，不包含遥测，不接收 API 密钥。AI 客户端可能把回答和读取内容发送给其模型服务；首次采访前说明这一点。本地存储不能被描述成“内容绝不离开电脑”。

真实日记、JSON 会话、输入文件、运行记录和缓存通过目录隔离与分发白名单排除在公共项目之外。示例必须标明 synthetic。用户可自行删除各类本地文件，但删除单个 Markdown 不等于删除其他副本或云端聊天记录。

完整隐私说明位于 Skill 的 references/privacy.md。

## 8. 长期分析的预定规则

v0.2 才实现历史读取和报告。按不同日期统计有效记录：已完成且至少有一条非空真实回答的记录有效；同一天多个会话只计一个日期；同会话多个导出版本只使用最新版本。

达到 7 个有效日期可提示周回顾，30 个可提示月度趋势。触发数量是产品门槛，不表示统计显著性或结论可靠性。分析必须逐指标报告缺失与有效样本数，不把相关关系称为因果，也不把缺失值按 0 统计。

未来行动追踪区分：用户是否选择尝试、是否执行、观察到的结果、其他可能解释。v0.1 通过原始问答和行动类别保留这些上下文，不伪造跟踪结论。

## 9. 验收

1. 完成或跳过全部 20 题后，客户端自动调用保存；日记原始问答、完成标记和来源齐全。
2. 答完 3 题后暂停并退出进程；新进程恢复第 4 题，原话、日期和进度一致。
3. 跳过题的答案为空；未知评分为空；提前结束的日记明确标记未完成并可继续。
4. 完成后修改答案重新保存，指标和总结更新，旧版文件内容不变。
5. 非法日期、时区、评分、任务数、来源编号、旧总结及跳序输入被拒绝。
6. 模拟写入失败，原 JSON/Markdown 不损坏；导出后会话更新失败可重试。
7. 中文、多行回答和反引号正确保留；YAML frontmatter 可用 safe_load 解析。
8. Skill 元数据、引用和 JSON 模板通过检查；固定白名单分发包不包含运行及私人目录。

真实提问质量与语义来源一致性由 AI 客户端试用核对，合成回放只验收确定性存储流程。当前验证环境为 Windows、Python 3.10.9；其他系统尚未实机验证。
